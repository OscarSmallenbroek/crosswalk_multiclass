tools/ -- build chain and test suite for crosswalk_multiclass
================================================================

This folder has two kinds of file: BUILD scripts, which generate the shipped
package in multiclass-addon/ from the source data in crosswalks/, and TEST
scripts, which check the result. Build scripts must run in order (each one
consumes the previous one's output). Test scripts can run in any order, any
time after the package exists, and change nothing.

See dev/DEVELOPMENT.md for the underlying data facts and design decisions;
this file only covers what to run and in what order.


BUILD CHAIN (run in this order)
--------------------------------

1. make_tables.do            [Stata]
   Reads the three source .dta files in crosswalks/ and writes the raw
   translation tables to build/ (git-ignored, created if missing):
     build/d_<source>_to_<scheme>.txt   -- one row per code, per scheme
     build/addon3_<source>.csv          -- every 3-digit code resolved
                                            through the minor -> sub-major
                                            -> major fallback
     build/labels_microclass.txt        -- the 77 microclass value labels
   Nothing downstream reads crosswalks/ directly; everything downstream
   reads build/. Re-run this whenever the source .dta files change.

2. make_addon.py              [Python, needs build/ from step 1]
   Wraps build/ into the shipped package: writes every
   multiclass-addon/_cwfcn_*.sthlp and _cwfcn_labels_mc_*.sthlp table, plus
   crosswalk_multiclass.sthlp's data-carrying siblings. Applies the one
   hand-set override (011/621, ISCO-88 only -- see dev/DEVELOPMENT.md).
   Imports citations.py for all reference/citation text, so both stay in
   sync automatically. Help-file wording here is USER-facing.

3. make_pkg.py                [Python, needs multiclass-addon/ from step 2]
   Writes multiclass-addon/crosswalk_multiclass.pkg and stata.toc by
   listing whatever is actually in multiclass-addon/ at run time -- so it
   must run AFTER step 2, not before. These two files are for
   -net install- from a local directory or GitHub raw URL. SSC does not
   use them (it builds its own .pkg from the RePEc template), which is why
   make_ssc_bundle.py excludes them from the SSC zip.

4. make_ssc_bundle.py         [Python, needs multiclass-addon/ from step 2]
   Zips multiclass-addon/ into dist/ (git-ignored, created if missing) as
   the bundle to email to the SSC archive maintainer, per
   http://repec.org/bocode/s/sscsubmit.html. Excludes crosswalk_multiclass.pkg,
   stata.toc and README.md -- repo-only files SSC does not want.


SUPPORTING MODULE (not run directly)
-------------------------------------

citations.py                  [Python, imported by make_addon.py]
   Shared reference blocks (author lists, DOIs, provenance notes) so the
   help files cannot drift out of sync with each other. Also carries the
   ASCII-hygiene helpers (to_ascii/assert_ascii) that step 2 uses to fold
   typographic punctuation and enforce the plain-ASCII + LF rule SSC
   requires. Edit this when a citation or reference wording changes, then
   re-run step 2 to propagate it -- and check crosswalk_multiclass.sthlp,
   README.md and _cwcasefcn_mcempstat.sthlp by hand afterward, since those
   three are hand-maintained and NOT regenerated by any script here.


TEST SUITE (run any time after the build chain, any order)
-------------------------------------------------------------

test_addon_live.do            [Stata; needs crosswalk, moremata, and the
                                built package on the adopath]
   The main correctness test, entirely through crosswalk itself (no
   Python, no other command to compare against -- crosswalk is both the
   thing under test and the only oracle available). Three kinds of check:
   internal consistency (every route to an answer must agree), external
   parity (our Macro-SEC must collapse to exactly crosswalk's own native
   ESeC), and structure (schemes must nest; bad input must fail safe).

test_installed.do             [Stata; needs crosswalk, moremata, and the
                                built package on the adopath]
   Confirms the package installs correctly: every .sthlp declared in
   crosswalk_multiclass.pkg exists and is readable by crosswalk, and
   nothing on disk is left undeclared.

test_ssc_compliance.do        [Stata; needs crosswalk, moremata, and the
                                built package on the adopath]
   Checks the SSC submission requirements that apply to a data-only add-on
   (no ado-file, no command name, so the command-naming and -version-
   requirements are satisfied vacuously): every table must behave
   correctly under -set varabbrev off-.


QUICK REFERENCE
-----------------

    do tools/make_tables.do
    python tools/make_addon.py
    python tools/make_pkg.py
    python tools/make_ssc_bundle.py

    do tools/test_addon_live.do
    do tools/test_installed.do
    do tools/test_ssc_compliance.do

All paths above are relative to the repository root
(D:/work/multiclass-package), which is also what every script assumes as
its working directory.
